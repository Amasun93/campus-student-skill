# 校区学员情况管理 - 项目记忆

## 项目背景
- 来源：大卫老师与校区校长的交流，探讨AI时代编程教育转型
- 痛点：校区学员信息全靠口口相传，顾问老师文化水平低、缺结构化思维
- 目标：用AI引导式追问，把顾问/老师脑子里的信息结构化，支撑挖需和课程推荐

## 产品形态决策
- 第一版：workbuddy Skill（先验证流程）
- 未来：可能升级独立App
- 数据格式要为迁移预留（不能写死在skill本地）

## 使用者与角色
| 角色 | 掌握信息 | 录入内容 |
|------|---------|---------|
| 顾问（销售） | 家庭背景 | 家庭情况、家长规划目标 |
| 老师 | 学生情况 | 课堂表现、学习进度、作品成果 |
| 校长 | 全部 | 查看汇总、决策推荐 |

## 核心工作流
```
老师/顾问各自workbuddy → skill采访追问 → 各自导出表格
                                                    ↓
                                          校长收集所有表格
                                                    ↓
                                  skill读取汇总 → 汇总表格(.xlsx)
                                                    ↓
                              (可选) AI补齐 + 决策标签 + HTML前端报告
                                                    ↓
                                      支持新表格汇入更新
```
- 分批交付支持：2-3周内录一部分就能给校长，校长看到完成率/百分比

## 关键约束
- 使用者文化水平低，skill必须主动追问、口语化提问、容忍"不知道"
- 唯一标识：学生姓名（中文正式名，**完整姓名含姓**），重名时用年级对齐
- 同校区同年级重名概率小
- **A字段去掉电话**（需要时让导家长手机号列表）
- 多校区支持v1就做（加校区字段，跨校联校设计）
- 成绩排名敏感，有大致水平就行，不要求具体排名
- 学校层次/是否科技特色校由AI补齐
- 采集方式：字段引导式（给字段让顾问讲→AI提取→只追问缺失关键信息），不是整段口述也不是一问一答填表
- 追问颗粒度：只追问必要重要的，不为追问而追问（例：知道小区就不用问自住/租房）
- 话术是参考不是脚本，要有活人感
- skill人格化：热情小管家/学校小助手，打招呼+介绍+确认身份+开始，完成给情绪价值
- 衡量指标：一老师50+学生，多老师一校区，一周内搞定
- AI教育性：不用每个都教育，给情绪价值即可，让老师顾问觉得做有价值的事+感受AI提效

## HTML前端（可选输出）
- Excel默认必给（看原始资料/手动摘表）
- HTML是可选，问校长需不需要再做
- 三页结构：
  - 页1：表格呈现+筛选（解决Excel太长）
  - 页2：校区分析报告（高净值占比、家长来源小区分布、校区理念等）
  - 页3：产品推荐画像（哪些家长适合推什么+百分比+画像筛选）

## 目标定位（重要）
- 学情管理是基础数据底座
- 目标是提高转化效率
- 转化效率靠校长思路，是skill和校长共创的地方，规则不写死

## 字段框架 v0.3（定稿，三层架构）

### 第一层：人工录入层（顾问/老师口述）
- A.基础标识：姓名(中文正式名完整含姓,必填)、昵称、年级、年龄、**校区**
- B.家庭背景与规划(顾问主录)：家长职业+单位性质、家庭结构、教育氛围、居住小区、**家长规划目标**、对AI认知度
- C.学生在校情况(老师主录)：学校名称、学校层次(AI补齐,含是否科技特色校)、成绩排名(大致水平即可)、性格特点、兴趣偏好、课堂表现、同伴关系
- D.在读课程与成果(老师主录)：已报名课程、在读课程、学习时长、作品成果、续费历史

### 第二层：AI补齐层（校长汇总时联网检索）
- 触发时机：校长汇总到完整汇总表后
- 范围：小区房价段/住户画像、周边学校学情考情科技特色、周边竞品机构、家庭消费力评估、其他补充
- 注意：只知道职业领域或大公司名，不知道具体工作单位
- 标注"AI补齐，请人工核实"

### 第三层：AI推算层（决策标签，系统自动）
- 支付力等级、适合推荐产品方向、续费风险、转介绍潜力、本月跟进优先级
- 推荐方向需要产品细节（Python/科创/信奥），后续问校长补充

## 多角色协作流程（定稿）

### 采集端（顾问/老师各自的workbuddy）
- 各自独立采集自己手上的学生名单，互不干扰
- 顾问和老师都录A基础标识（姓名、年级、年龄、电话）
- 顾问主录 A+B（家庭背景与规划），可选补D
- 老师主录 A+C+D（学生在校情况+在读课程与成果）
- 老师手上学生可能50+，需分批采集 → 名单进度管理是刚需
- 采访启动：先录名单作为待办 → 每次选采一两个 → 采完打勾

### 汇总端（校长的workbuddy）
- 校长收集所有个人表格（Excel/CSV）
- 用skill读取多份表格 → 按姓名合并（重名用年级对齐）
- AI联网补齐第二层字段
- 系统推算第三层决策标签
- 输出带标签的汇总表

### 信息冲突处理（A+C方案）
- 都保留，标注来源（"顾问认为…/老师反馈…"）
- 冲突信息flag给校长人工核实
- 视角差异本身是重要信息（如家长在销售前/上课后两个样）

## 待明确事项
- 决策标签推荐逻辑：需要产品细节（Python/科创/信奥具体产品线）
- 实施路径：用skill引导式对话采集校长的推荐思路 → 应用到产品推荐 → 不同校区情况不同，需按学员画像分类后再做推荐
- 采访话术设计：实现细节，PRD阶段或后续打磨

## 关键交付物约束（新增）
- JSON本地存储仅作内部缓存，尽量简单
- **必须导出Excel格式**（不是CSV）—— 老师搞不懂JSON/CSV，只能打开Excel
- skill本地可存JSON做进度管理，但最终交付物必须是.xlsx
