# 字段说明（v1.6.0 字段字典）

> 本文档定义校区学员情况管理 Skill 的完整字段框架，来源于 PRD v1.6 §4。与 SKILL.md v1.6.0 同步。

## 三层架构总览

```
第一层:人工录入层 → 第二层:AI补齐层 → 第三层:AI推算层
  A基础标识            小区房价段          支付力等级
  B1家庭背景           周边学校            推荐产品方向
  B2销售漏斗           学校层次+科技特色    续费风险
  C在校情况            周边竞品            转介绍潜力
  D1课程成果           家庭消费力          跟进优先级
  D2学情履历           推荐话术素材        学情画像（8类标签）
  E学员细节备注
  F三路信源
```

## 第一层：人工录入层

### A. 基础标识（顾问+老师共录）

| 字段 | 类型 | 必填 | 录入角色 | 说明 |
|---|---|---|---|---|
| 姓名 | String | ✅ | 顾问+老师 | **完整姓名含姓**（大名全名），重名对齐依据 |
| 昵称 | String | | 顾问 | 平时叫的小名 |
| 年级 | String | ✅ | 顾问+老师 | 重名对齐依据；老师侧录入D2后由系统自动校验更新 |
| 年龄 | String | | 顾问+老师 | 不确定按年级估，用户可改 |
| 所在校区 | String | ✅ | 顾问+老师 | 多校区支持，首次确认后默认带入 |

> **电话字段不采集**。需要时让校长导家长手机号列表。

| 居住小区 | String | | AI补齐入口，挺重要 |

| 家长教育取向 | String | | 鸡血型/理念型/跟风型，顾问的第一判断，直接决定推荐方向和话术策略 |

| B2.08 | 顾问复盘 | AI生成+顾问确认，200字内 | | AI+顾问 | 录完后小朱口头给建议，顾问确认后同时落盘 |

**阶段感知采集重点**：

| 当前阶段 | 采集重点字段 |
|---|---|
| 新签挖需 | B1家庭背景 + B2.01客户来源 + B2.02对接次数 + B2.03累计跟进时长 + B2.05最初兴趣点 + B2.06介绍过的产品 |
| 诺访 | B2.07堵点（主观题深挖）+ B2.06介绍过的产品 + B2.02对接次数 + B2.03累计跟进时长 |
| 在读更新 | B1家庭背景变化 + D2.12家长新期待 + D2.11家长关注度（是否有疲态） |

**顾问复盘内容按阶段定制**：

| 阶段 | 复盘内容 |
|---|---|
| 新签挖需 | 分析客户画像 + 推荐产品方向 + 下一步行动建议 |
| 诺访 | 分析堵点 + 转化策略建议 |
| 在读更新 | 分析续费风险 + 家长状态 + 推荐续费话术 |

### F. 三路信源字段说明（家庭背景交叉补充）

<!-- 内部参考：三路信源为v1.6新增机制 -->

家庭背景信息有三路信源，**并列保留，不做强制合并，仅标注来源**：

| 信源 | 录入角色 | 字段形式 | 说明 |
|---|---|---|---|
| B1 家庭背景（顾问结构化） | 顾问 | 9个结构化字段 | 顾问初次接触家长时采集，结构化程度高 |
| B_cross_teacher 家庭背景_老师补充 | 老师 | 自由文本 | 老师日常接触家长时口述补充，可能发现顾问没注意到的信息 |
| B_cross_principal 家庭背景_校长补充（未来） | 校长 | 自由文本 | 预留接口，校长层面观察到的家庭信息 |

**冲突处理**：三路信源都保留，不做强制合并。汇总时在同一字段区域并列展示，标注来源。冲突信息flag给校长核实。

**价值**：隐形信息的交叉验证。顾问看到的是家长初次接触时的表现，老师看到的是日常接送、群内互动的状态，两者交叉能发现更深层的情况。

## 第二层：AI补齐层（校长汇总时联网检索）

| 补齐字段 | 数据来源 | 标注 |
|---|---|---|
| 小区房价段/住户画像 | 联网检索（居住小区） | "AI补齐,请核实" |
| 周边学校学情考情 | 联网检索（学校名称） | 同上 |
| 学校层次+科技特色详情 | 联网检索（学校名称+公众号喜报） | 同上，含竞赛传统和近期科技竞赛成绩 |
| 周边竞品机构 | 联网检索（小区/学校） | 同上 |
| 家庭消费力评估 | 综合职业+小区推算 | 同上 |
| 推荐话术素材 | 综合学校科技特色+竞赛成绩+学员画像+校区推荐规则 | 同上，直接给顾问可用的交流理由和切入点 |

### 联网搜索指引（方向性，非死规则）

| 维度 | 指引内容 |
|---|---|
| 检索方向 | 围绕"居住小区""学校名称"两个锚点，检索房价段/住户画像、周边教育资源、周边竞品机构、学校层次与特色 |
| 学校深度检索 | ① 是否科技特色校/科创特色校；② 学校公众号是否发布过科技/编程/信息学竞赛喜报；③ 学校是否有参加NOI/CSP/蓝桥杯等编程竞赛的传统和成绩；④ 学校是否有编程/STEAM/创客类社团或课后课程 |
| 检索技巧 | ① 小区名+城市名组合搜索，避免同名小区混淆；② 学校名加"科技特色/科创/喜报/竞赛获奖"关键词；③ 竞品搜索用"小区名+编程/少儿编程/STEAM"组合；④ 交叉验证多个来源取共识值 |
| 灵活执行 | 模型根据自身能力选择检索策略：能联网就用联网，不能就基于知识库推断并标注；检索失败不阻塞，标"待补齐" |
| 结果标注 | 所有AI补齐值统一附"(AI补齐,请核实)"；学校科技特色详情要写清楚具体内容 |

### 降级策略

联网失败 → 该字段标"待补齐"，不阻塞流程。分层保底：搜索引擎摘要→多源交叉验证→知识库推断→标待补齐。

## 第三层：AI推算层（决策标签，系统自动）

| 决策标签 | 推算依据 | 输出形式 |
|---|---|---|
| 支付力等级 | 职业+小区房价段+消费力 | 高/中/低 |
| 适合推荐产品方向 | 家长教育取向+家长竞赛认知+校区配置推荐规则+学生画像 | 课程名 |
| 续费风险 | 学习时长+课堂表现+续费历史+距上次沟通+家长关注度+疲态 | 高/中/低 |
| 转介绍潜力 | 家庭结构+家长规划+对AI认知度 | 高/中/低 |
| 本月跟进优先级 | 综合以上四项 | 1-5星（⭐⭐⭐⭐⭐） |

> 决策标签阈值从 `校区配置.json` 读取，每个校区不同，Skill自适配。

## 学情画像标签体系（v1.6新增）

学情画像是对学员的综合判断标签，基于D2学情履历+B2销售漏斗+C在校情况多维推算。

### 8类标签定义

| 标签 | 定义（满足全部条件） | 价值 |
|---|---|---|
| 竞赛冲刺型 | 白名单比赛非空 且 等级考含中高级 且 家长关注度=高 | 重点跟进对象，直接推竞赛产品 |
| 科创潜力型 | 兴趣偏好含"科创/机器人/编程" 且 课堂表现含"积极/主动" 且 (白名单比赛为空 或 等级考≤初级) | 有潜力但还没出成绩，适合引导竞赛路径 |
| 兴趣探索型 | 兴趣偏好非空 且 在读时长<6个月 且 等级考=未考 | 新生阶段，重在培养兴趣和习惯 |
| 续费稳定型 | 在读时长≥12个月 且 家长关注度=高 且 疲态=无 | 续费基本盘，维持即可 |
| 流失风险型 | (家长关注度=低 或 群内回复=慢/无回复) 且 疲态=轻度/明显 且 家长新期待为空 | 预警对象，需主动干预 |
| 高净值待挖型 | (老师侧支付力含"研学/lab/VEX" 或 支付力=高) 且 白名单比赛为空 且 (等级考=未考 或 ≤初级) | 高价值客户，适合推高端产品 |
| 谨慎观望型 | (累计跟进时长≥2个月 或 对接次数≥3) 且 堵点非空 且 当前阶段≠在读更新 | 诺访卡住的对象，需转化策略 |
| 基础夯实型 | 在读时长<12个月 且 (等级考≤初级 或 未考) 且 课堂表现含"稳定/踏实" 且 白名单比赛为空 | 稳扎稳打型，适合续推基础课 |

### 推算规则

1. **多标签共存**：一个学员可以同时命中多个标签
2. **字段缺失视为不满足**：任何条件涉及的字段为空，则该条件不满足
3. **命中≥3个时按优先级取前2个为主标签**：
   - 优先级排序：流失风险型 > 高净值待挖型 > 竞赛冲刺型 > 谨慎观望型 > 续费稳定型 > 科创潜力型 > 兴趣探索型 > 基础夯实型
   - 流失风险型最高优先（预警价值最大），基础夯实型最低
4. **命中<3个**：全部命中的标签都作为主标签展示
5. **命中0个**：标"待画像"（字段不足，后续补齐后重算）

### 推算时机

| 时机 | 执行方式 | 说明 |
|---|---|---|
| 老师采集完D2后 | 指令层AI即时推算（不调Python） | 给老师快速参考，老师确认/忽略 |
| 校长汇总时 | 系统调用 calculate_student_profile 统一重算 | 写入"学情画像"列，以系统推算为最终值 |
