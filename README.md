校区小助手"小朱"引导顾问、老师和校长，通过聊天式交互把零散的学员信息变成结构化 Excel 数据。采集完成后自动汇总、AI 补齐、决策标签推算，可选生成 HTML 可视化报告——全流程一个 Skill 搞定。

## 背景

编程教育校区在学员信息管理上面临几个核心挑战：

- **信息靠口口相传**：哪个家长预算充裕、哪个孩子适合推信奥，全凭老师顾问"口头交接"，换人就丢失
- **不同角色各知道一半**：顾问掌握家庭背景，老师了解课堂表现，但两边的信息从不汇合
- **转化决策凭感觉**：续费提醒靠记忆，课程推荐凭经验，没有数据支撑容易错失机会
- **录入门槛高**：传统 CRM 系统要填几十个字段，一线员工抵触大、完成率低

本 Skill 用聊天式采集降低录入门槛，用三层字段架构（人工录入 → AI补齐 → AI推算）把信息逐步丰富，用角色分流保证各录各的互不干扰，最终汇合到校长手里形成决策依据。

> Skill = 采集策略 + 数据架构 + 决策逻辑，不是填表工具。让校区员工像聊天一样完成信息录入，AI 自动提取、结构化、补齐、推算。

## 能力

| 能力 | 说明 |
|------|------|
| 聊天式采集 | 小朱给提示 → 你聊着天说 → AI 提取结构化 → 只追问缺失关键信息，不填表 |
| 角色分流采集 | 顾问录家庭背景与规划，老师录在校情况与课程成果，互不干扰 |
| 分批交付 | 采一部分就能导出，校长可见完成率，不用等全部采完 |
| 汇总合并 | 多份 Excel 按姓名合并，信息冲突双保留并标注来源 |
| AI 补齐 | 联网检索小区房价、学校层次、周边竞品等，标注"AI补齐请核实" |
| 决策标签 | 从校区配置读阈值，自动推算支付力 / 续费风险 / 转介绍潜力 / 跟进优先级 / 推荐方向 |
| HTML 报告 | 三页结构：全员表格+筛选 → 校区分析 → 产品推荐画像 |
| 多校区支持 | 校区字段贯穿全流程，首次确认后默认带入 |
| 保底机制 | Python 不可用时核心功能不受影响，workbuddy 内置工具兜底 |

## 产品定位

> 学情管理是基础数据底座，最终目标是提高转化效率。

- **底座层**（Skill 固化）：学员信息采集 → 结构化 → AI补齐 → 汇总合并 → 数据分析
- **转化层**（校长共创）：推荐规则配置 → 决策标签推算 → 产品推荐画像

转化层的关键在于——推荐规则不是写死的，而是校长和 Skill 共创。不同校区、不同学员画像，推荐策略自然不同。

## 安装

### 前置条件

- workbuddy 平台账号
- Python 3.8+（用于 Excel 处理脚本）
- openpyxl >= 3.1.2

### 安装步骤

1. 将本 Skill 文件夹放入 workbuddy 的 skills 目录
2. 安装 Python 依赖：
   ```bash
   pip install openpyxl>=3.1.2
   ```
3. 在 workbuddy 中说"用学情管理 skill"即可激活

> 保底机制：即使 Python 不可用，核心功能（采集→缓存→导出→汇总）仍可通过 workbuddy 内置工具完成。

## FAQ

**顾问/老师不太会用电脑怎么办？**
全程只用和小朱聊天，不用填表。AI 自动提取结构化。导出的 Excel 打开就能看。

**数据安全吗？**
数据存在本地（JSON 缓存 + Excel 文件），不上传云端。开源版本不含任何真实学员数据。

**多个校区能用吗？**
能。校区字段贯穿采集/汇总/分析全流程，首次确认后默认带入。

**Python 没装怎么办？**
有保底机制。Python 不可用时，workbuddy 用内置工具直接处理数据，核心功能不受影响。

**联网检索搜不到怎么办？**
搜不到就标"待补齐"，不阻塞流程。校长可后续手动补充。

**推荐规则能改吗？**
能。校长随时跟小朱说"改下配置"，重新进入校准流程即可。

## 设计哲学

> Skill 不是填表工具，是聊天式信息结构化引擎。

核心 tradeoff：
- **聊着天说 vs 一问一答填表**：给字段提示让顾问讲，AI 提取，只追问缺失关键信息。效率比填表高，体验比口述好。
- **只追问必要 vs 为追问而追问**：知道小区就不用问自住/租房，追问颗粒度克制。
- **双保留 vs 强覆盖**：顾问和老师视角不同是重要信息，冲突不覆盖，双保留给校长核实。
- **推荐规则共创 vs 写死**：不同校区情况不同，推荐策略由校长和 Skill 共创。
